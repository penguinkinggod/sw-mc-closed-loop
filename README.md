这是一个面向**限定轴类、套类零件**的二轴车削 CAD/CAM 自动化原型。

项目尝试把一份结构化参数接到下面这条链路：

```text
参数 JSON
    ↓
轮廓几何与工艺清单
    ↓
语义 DXF + process.json
    ↓
Mastercam 母模板的隔离副本
    ↓
工序筛选、克隆、绑链、再生
    ↓
逐工序 NC
```

SolidWorks 模型和 STEP 是设计侧的并行核验支路；工程图由 STEP 读取后单独生成。项目不是“输入任意图纸就能自动编程”的通用 AI 系统，而是一个限定零件族、规则驱动的个人工程原型。

## 关键设计

### 1. DXF 图层表达加工意图

DXF 图层不是单纯的几何分组，而是给 Mastercam 的工序绑定提供明确名字，例如：

```text
S1_OD_ROUGH
S1_OD_FINISH_01
S1_ID_FINISH_02
S1_THREAD_EXT_M10
```

每个需要绑定的图层还要满足链连续性和最小图元数等检查。这样，参数变化时可以重新生成轮廓，而不是依赖旧文件里的鼠标选择。

### 2. 母模板与案例副本分离

Mastercam 母模板包含一组经过人工调整的车削工序。实际案例先复制出独立副本，再在副本上筛选、克隆、绑链和后处理。这个约束是为了避免一次案例的修改污染后续案例。

### 3. 参数同源，但各环节仍需校验

模型、DXF、工艺 JSON 和工程图都由同一组输入参数或其派生数据驱动，但它们按不同用途生成：

- SolidWorks 负责设计侧模型；
- DXF 负责车削轮廓和语义链；
- `process.json` 负责工序意图；
- 工程图从 STEP 读取几何并补充标注。

因此，“参数相同”不能替代模型、链、刀路、NC 和图纸的逐层检查。

## 当前边界

- 主要面向限定的二轴车削轴类/套类零件，不是通用 CAD/CAM 系统。
- 没有完成 Mastercam 刀路仿真、独立碰撞检查和真实机床试切。
- NC 做过结构性文本检查，但不能据此保证机床安全。
- SolidWorks 自动生成的模型仍需人工打开确认；部分案例存在草图约束状态需要继续检查。
- 工程图的复杂内孔和密集标注仍有版面限制。
- 机器视觉、PLC、数字孪生和多轴加工不属于本仓库当前已完成能力。

完整边界见 [`docs/LIMITATIONS.md`](docs/LIMITATIONS.md)。
